# ppCoffe · 产品与页面规划

> 冲煮 + 烘焙双链路咖啡记录工具。核心命题：**把「风味」作为中枢，把冲煮参数、冲煮曲线、烘焙曲线三者的因果关系显式化**。

---

## 0. 一句话定位

一个能同时记录「怎么冲的」和「怎么烘的」的咖啡实验室，用**风味**把两条链路串起来：
`烘焙曲线 → 豆子状态 → 冲煮参数 → 冲煮曲线 → 风味表现 → 反推下一杯怎么改`

## 1. 调研结论

### 1.1 冲煮记录类 App 竞品画像

| **PUCK YEAH** | 端上 AI 调参建议 | 端侧 AI 给出「下一杯改什么」、豆库社区、CSV/JSON 导出 | 无 iCloud、蓝牙秤未发货 |

| **ShotTune** | 极简意式日志 | 自动算粉液比、与上一杯差异对照 | 只做意式 |
| **Dial In Espresso** | 干净日志 + 导出 | CSV/PDF 导出、极简 | 只记录不指导 |
| **Filtru** | 手冲计时器 | 分段注水引导 | 无风味记录 |

**行业共识（四条必须做）**：
1. **豆子管理是地基** —— 烘焙日期追踪（养豆期）决定推荐度，是所有 App 的标配
2. **「与上一杯 / 同豆历史对比」是最高价值功能** —— 静态记录不如对比有价值
3. **数据导出是刚需** —— CSV/JSON，用户要能带走自己的数据
4. **风味记录普遍缺失或过于简化** —— 这是 ppCoffe 的机会点

### 1.2 SCA 风味与感官体系（记录字段的权威依据）

- **SCA 风味轮**（与 WCR 合作，2016 改版）：内环 **9 大类** → 中环 30+ 子类 → 外环 80+ 具体描述词
  - 花香 Floral / 果香 Fruity / 酸·发酵 Sour·Fermented / 绿·植物 Green·Vegetative / 其他 Other / 烘烤 Roasted / 香料 Spices / 坚果·可可 Nutty·Cocoa / 甜 Sweet
  - 每个词背后是 **WCR 感官词典**（110 条属性）的物理参照物（如「蓝莓」= 蓝莓+水），保证不同人记录的是同一个东西
- **2024 新标准 CVA**（已取代 2004 版杯测表）：
  - 102-2024 样品制备与品饮机制：8.25g / 150ml（±0.2g）、杯容 200–350ml、研磨过 20 目 70–75%、水 93±3℃、破渣 3–5 分钟、约 70℃ 起评
  - 103-2024 描述性评估：**0–15 强度量表** + 勾选式描述词清单
  - 104-2024 情感性评估：9 分制 × 5 杯一致性扣分（全部 9 分 = 100，全部 5 分 = 79），每杯非均一扣 2 分、有缺陷扣 4 分
- **传统 100 分制**（仍广泛流通）：干香 / 风味 / 酸质 / 醇厚 / 余韵 / 平衡 / 干净杯 / 甜感 / 整体印象 / 一致性；**80 分以上为精品**
- **感官科学关键点**：
  - 酸质（acidity，正面：明亮活泼）≠ 酸涩（sour，负面：欠萃尖锐）—— 记录必须区分
  - 风味 80–90% 来自**鼻腔retro嗅觉**（吞咽后呼气），不是舌头
  - **品饮温度分段**：热 / 温（70–75℃，最佳风味表达）/ 凉，风味随降温阶梯式变化 → 记录应支持「温度段」维度
  - 萃取不足 → 尖酸、缺甜、余韵短；萃取过度 → 苦、干涩、空洞

### 1.3 烘焙曲线体系

- **三通道曲线**：豆温 BT / 环境温 ET / 升温率 RoR
- **关键事件**：Charge（投豆）→ Turning Point（回温点）→ Dry End（脱水结束）→ First Crack（一爆）→ Drop（下豆）
- **关键指标**：
  - **DTR 发展比** = 一爆后时间 / 总时长（1:30 / 9:00 ≈ 17%）；批次间漂移是「风味变了」的第一排查项
  - **Turning Point**：投豆后豆温开始回升的时间与温度
  - **失重率 Weight Loss**、总时长、投豆/出豆量、Drop 温度与一爆温度差
- **阶段划分与典型占比**：脱水 Drying ~40% / 梅纳 Maillard ~46% / 发展 Development ~13%
- **RoR 健康形态**：初期 15–25℃/min → 梅纳期平稳下降 → 一爆前 5–15℃/min
  - **Crash（骤降）** → 焦苦/ underdeveloped；**Flick（尖刺）** → 焦糊/着色不均
- **生态**：Artisan（免费开源本地，事实标准，.alog 格式）、Cropster（云端商业）、Profiler 2、Kaffelogic
- **核心工作流**：目标 Profile 叠加 + 同机历史批次叠加 + 一爆/下豆事件标记 + 批次间指标漂移对比

## 2. 领域模型

```
Bean（豆批次）
 ├─ RoastBatch（烘焙批次） 1..n ── curve: BT/ET/RoR + events
 └─ BrewRecord（冲煮记录）  1..n ── curve: (t, weight, flowRate) + steps
                              └─ FlavorProfile（风味画像）
Recipe（配方模板）── method + 参数区间 + 分段注水计划
Equipment（器具/设备）
```

| 实体 | 关键字段 |
|---|---|
| **Bean** | 名称、烘焙商、产地/产区/庄园、品种、海拔、处理法（厌氧/日晒/水洗/蜜处理）、烘焙日期、烘焙度（浅/中/深 + Agtron）、含水量、重量、备注 |
| **RoastBatch** | 批次号、beanId、设备、投豆量/出豆量、失重率、总时长、TurningPoint、FirstCrack（时间+温度）、Drop（时间+温度）、DTR、阶段占比、事件序列、曲线点列、来源（实时/手工/导入）、目标 profileId、杯测分 |
| **BrewRecord** | beanId、roastBatchId、method、equipment、dose、water/yield、time、temp、grind、ratio、preinfusion、steps（注水分段）、flavorProfile、extractionGuess、备注 |
| **FlavorProfile** | 六轴强度（酸质/甜感/醇厚/风味/余韵/平衡，各 0–10）、风味轮标签（9 分类 + 具体描述词 + 各自强度）、缺陷标记、整体印象分、温度段 |
| **BrewCurvePoint** | t（秒）、cumulativeWeight（g）、instantFlow（g/s）、stage（闷蒸/萃取/滴滤结束） |

## 3. 冲煮方式 × 风味联动（核心差异化）

这是本产品最关键的设计：**方式不是下拉框里的一个枚举值，而是决定「该喝到什么味、用什么参数区间」的方法论对象**。

### 3.1 方法元数据表（每个方式自带参数区间 + 风味画像 + 词库子集）

| 方式 | 原理 | 研磨 | 粉水比 | 水温 | 时间 | 压力 | 目标风味画像 | 推荐词库子类 |
|---|---|---|---|---|---|---|---|---|
| 手冲 V60 | 重力滴滤 | 中细 | 1:15 (1:13–1:18) | 88–96℃ | 2:30–3:30 | 0 | 高酸、干净、花果香、层次 | 果香/花香/酸·发酵 |
| 手冲 Kalita | 平底三孔 | 中细 | 1:15 | 88–96℃ | 3:00–4:00 | 0 | 更均衡稳定、甜感清晰 | 果香/坚果可可 |
| 手冲 Origami | 锥形 | 中细 | 1:15 | 90–93℃ | 3:00–3:30 | 0 | 流速顺畅、层次丰富 | 果香/花香 |
| Chemex | 厚滤纸 | 中粗 | 1:16–1:17 | 92–95℃ | 3:30–5:00 | 0 | 极干净、透明、轻盈 | 花香/绿·植物/甜 |
| 法压壶 | 浸泡+压滤 | 粗 | 1:15–1:18 | 90–92℃ | 4:00 | 0 | 醇厚、油脂感、酸低甜高 | 坚果可可/其他 |
| 虹吸壶 | 气压差循环 | 中细 | 1:12–1:15 | 90–92℃ | 1:00–1:30 浸泡 | 极低 | 香气保留高、圆润 | 香料/其他/甜 |
| 摩卡壶 | 蒸汽压力 | 细 | 1:5–1:10 | 沸腾离火 | 2–3 分 | ~3 bar | 焦糖化、浓缩与滴滤之间、浓度 12–15% | 烘烤/坚果可可/香料 |
| 意式浓缩 | 高压 | 极细 | 1:2 (1:1.5–1:3) | 90–94℃ | 25–30s | 9 bar | 高浓度、Crema、甜苦集中、醇厚 | 烘烤/坚果可可/甜 |
| 爱乐压 | 浸泡+微压 | 中细 | 1:12–1:16 | 85–92℃ | 1:30–2:00 | 0.35 bar | 可切换美式/浓缩、醇厚 | 其他/坚果可可 |
| 气压壶 FP-1 | 气压 | 中细 | 1:12–1:16 | 85–92℃ | ~2:00 | ~0.5 bar | 油脂厚、酸低甜高 | 坚果可可/甜/其他 |
| 冷萃 | 长时间浸泡 | 粗 | 1:8–1:15 | 冷藏 | 12–18 h | 0 | 酸度低、甜突出、pH 5.5–6 | 甜/其他/坚果可可 |

### 3.2 正向联动：选方式 → 自动带出一切

选择「意式浓缩」后，表单立刻变成意式专属形态：

- 参数表单切换为：粉量 → 目标液重 → 萃取时间 → 压力档位 → 粉床信息 → 预浸
- **粉液比自动计算并校验**（1:2 ± 容差，超出标黄提示「可能欠萃/过萃」）
- 水温提示 **90–94℃**，研磨提示「极细（面粉状）」
- 风味词库只展示适合意式的子类（烘烤/坚果可可/甜/香料）
- 风味雷达图预先画出**该方式的目标风味基线**，用户打分后实时显示偏差
- **黄金区间锚点提示**：手冲 TDS 1.15–1.45% / 萃取率 18–22%；意式 TDS 8–12%

### 3.3 反向联动：录风味 → 诊断下一杯怎么改（真正的智能点）

用户打完风味分后，系统对比「该方式的目标风味基线」，输出偏差与处方：

| 观测到的风味 | 诊断 | 处方（按优先级） |
|---|---|---|
| 尖酸、缺乏甜感、余韵短 | 萃取不足 | 磨细 ↑ / 粉量 ↑ / 水温 ↑ / 延长时间 / 加强搅拌 |
| 苦、干涩、发干、空洞 | 萃取过度 | 磨粗 ↓ / 粉量 ↓ / 水温 ↓ / 缩短时间 |
| 酸质够但甜感缺失（尤其浅焙手冲） | 萃取不均 / 水质或研磨问题 | 改善搅拌均匀度、改用更高硬度水质、检查细粉 |
| 意式出现尖酸锐利 | 浓度放大酸质 | 换更浅水洗豆或降深度烘焙 / 加深烘焙换风味结构 |
| 风味淡薄如水 | 粉水比过低或萃取不均 | 增粉 / 改螺旋注水 |
| 焦糊烟熏 | 局部过热或烘焙过深 | 检查烘焙曲线（crash/flick）/ 修正注水稳定性 |

**偏差可视化**：风味雷达图上画出「目标基线轮廓」与「本次实测定轮廓」的叠加差值，一眼看出是「酸超了」「甜欠了」还是「整体偏平」。

### 3.4 烘焙 ↔ 冲煮联动

- Bean 下挂多个 RoastBatch，冲煮记录可关联到具体烘焙批次
- **对比视图**：「这锅豆的烘焙曲线」与「用它冲出来的风味」并列 —— 若某批次 DTR 异常且风味同步劣化，可直接归因到烘焙
- 养豆期提示：烘焙后 0–7 天建议养豆、7–21 天为赏味期、> 30 天风味衰减，首页主动提示

## 4. 曲线生成规则

用户要求「根据设置的内容进行生成」。三种数据来源模式，前端统一抽象为 `CurveSource`：

### 4.1 冲煮曲线

| 模式 | 输入 | 生成规则 | 适用 |
|---|---|---|---|
| **plan**（理论生成） | method + 分段注水计划 | 按分段（闷蒸/段1/段2/滴滤结束）构造目标重量折线 → 单调三次样条平滑 → 按阶段着色 | 手冲，无需硬件 |
| **keypoint**（关键点） | 用户在计时中打的 3–6 个关键点（时刻+重量） | 分段线性插值 → 平滑 → 补齐阶段边界 | 手冲、意式 |
| **device**（设备采集） | 蓝牙秤 / 导入 CSV | 原始 (t, weight) 序列 → 去噪 → 计算瞬时流速 g/s → 阶段切分 | 全方式（Beanconqueror 模式） |

**instantFlow** 由累计重量差分求得：`flow(t) = dW/dt`，需平滑窗口（建议 3–5 点滑动平均）以消除称重抖动。

**意式特殊模板**：预浸段（0–3s，压力 3 bar）→ 萃取段（9 bar）→ 泄压段，可直接由参数生成标准压力剖面 + 重量剖面。

### 4.2 烘焙曲线

| 模式 | 输入 | 生成规则 |
|---|---|---|
| **keypoint** | Charge / TP / DE / FC / Drop 事件 + 关键温度 | 按节点构造 BT 折线（对数时间轴）→ 平滑 → 差分求 RoR |
| **live** | 实时打点（含温度读数） | 边录边绘制，结束落库 |
| **import** | Artisan `.alog` / Roest 分享链接 / CSV | 解析 → 字段映射 → 落库，保留原始文件 |

**RoR 计算**：`RoR(t) = dBT/dt`，采用中心差分 + 30s 中心窗口平滑（对齐 Artisan 算法），并提供「零延迟复算」开关用于复盘。

**阶段自动切分**：由事件标记切分；缺标记时按温度阈值自动推断（DE ≈ 150–160℃ 转折、FC 由听感或曲线拐点标注）。

## 5. 信息架构与页面清单

底部 3 个 Tab：**首页 · 记录 · 豆仓**；设置/我的收进首页右上角。

> **实现调整（已落地）**：原规划中的「曲线」独立 Tab 已取消。
> 曲线不作为一个平级模块存在，而是**归属到豆仓里的具体豆子**——
> 每支豆子下面挂自己的冲煮曲线与烘焙曲线，对比也只在该豆的历史之间进行。
> 理由：曲线脱离「哪支豆、哪一炉烘的」就没有意义，独立 Tab 反而制造了无归属的数据。
> 底部导航因此由 4 项收缩为 3 项，「豆库」更名为「豆仓」。

## 6. 关键交互流程

### 6.1 一次冲煮（主链路）

```
首页「手冲」按钮
  → B2 选方式（V60 / 手冲通用 / 收藏配方）        [方式联动带出风味基线]
  → B3 参数录入（粉量/水量/水温/研磨）             [实时算粉液比，越界提示]
  → B4 实时计时器（分段注水引导 / 可选接蓝牙秤）
  → B5 曲线（自动 plan 生成 or 关键点 or 设备采集）
  → B6 风味记录（六轴 + 风味轮 + 缺陷）
       └→ 立刻输出「偏差诊断 + 下一杯处方」        ★ 差异化高点
  → B7 详情（可对比上一杯 / 同豆历史）
```

### 6.2 一次烘焙

```
豆仓 → 某豆子 → 「开始烘焙」
  → D2 实时记录（投豆 → 打点 TP/DE/FC/Drop + 温度读数）
  → 曲线自动生成（BT/ET/RoR + 阶段染色）
  → D3 详情（指标卡：DTR / 失重率 / 阶段占比）
  → D4 与目标 Profile、历史批次叠加
  → 关联杯测分 → 回写到豆子
```

## 7. 数据分析与联动洞察（P5）

| 洞察 | 说明 |
|---|---|
| 风味随烘焙日期的曲线 | 同一豆 0/7/14/21/30 天的风味雷达叠加 → 直观看到赏味期 |
| 参数漂移 | 同一豆历史冲煮的粉液比/时间/研磨散点 + 风味色阶 → 找到最优解邻域 |

| 一致性 | 同豆同参数的多次冲煮风味方差 → 冲煮稳定性评分 |

## 9. 主要风险与对策

| 风险 | 对策 |
|---|---|
| 小程序主包 2MB 限制 | 图表库按需引入；曲线页/烘豆页做**分包**；字体与素材走 CDN 或分包 |
| 小程序 `setData` 性能 | 曲线数据不进 page data，Canvas 直绘；列表卡片只带摘要字段 |
| 跨端差异（存储/网络/常亮/分享） | 抽象 `platform` adapter 层，业务层零平台分支 |
| 风味词库录入负担过重 | 三层降级：快速模式（六轴滑块）→ 标准模式（六轴+词库）→ 杯测模式（SCA 全字段） |
| 后端未就绪 | 前端内置 Mock Adapter + MSW/本地 JSON 切换，不阻塞前端开发 |
| 蓝牙秤生态碎片化 | 先做「标准 CSV 导入 + 手输关键点」，蓝牙作为增强功能 |
